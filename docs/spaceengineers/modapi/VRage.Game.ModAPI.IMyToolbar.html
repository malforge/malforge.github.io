IMyToolbar

Assembly: VRage.Game.dll

public interface IMyToolbar: IMyToolbarSlots

A toolbar a player can configure: a block's action toolbar, a cockpit's own toolbar, or a player's character toolbar. Obtained from a block's IMyToolbarProvider component, and for players from CharacterToolbar , which accepts writes, or Toolbar , the session's read only copy. The inherited members address the slots a keyboard player uses; the gamepad slots are a parallel set reached through GamepadSlots .

Properties

Member Description
GamepadSlots The parallel set of slots a gamepad player uses. Null on a character toolbar, which has no gamepad slots a player can reach; check for it before use.

SlotCount is always four, whatever this toolbar's is, because a page maps to the four directions of a pad rather than to the owning block. Pages grow as a player fills them and only those up to the last filled slot survive a save, so do not store a gamepad slot index between sessions.
Type The toolbar's type. Action toolbars are ButtonPanel ; a cockpit's own toolbar reports Ship or Seat , its build toolbar BuildCockpit , and a character toolbar Character .
ItemCount Total number of slots, SlotCount multiplied by PageCount .

Trigger(int) Runs the item in a slot, as a player pressing it would. A block toolbar is owned by the server, so this runs there and refuses anywhere else; a mod gets itself to the server by sending its own message and calls this from there. What the item does replicates as usual.

An item that is not currently available does not run: a block action needs its target to share a grid group with the block owning the toolbar.

A slot holding a definition rather than an action - a block to build, a tool - selects it for whoever is at the keyboard. That is the expected thing in single player and nothing useful on a dedicated server, where nobody is.
